## 2. Retrieval policy — read this before searching

Order, every time:

1. **Graph first, for structure.** `search_graph`, `trace_path`, `query_graph`,
   `get_architecture`. This is the codebase's structured representation — use it
   before reading files by hand.
2. **`search_code` or grep for literal or non-code text**, or when graph coverage
   is insufficient for the question.
3. **`get_code_snippet`** for exact source of a symbol you already have a
   qualified name for.
4. **Broad `Grep`/`Glob` sweeps are the last resort**, not the first move — only
   when the graph and `search_code` both fail to locate the target.

## 3. Evidence rules

- Cite the qualified symbol and file path for every structural claim.
- Before answering, run one batched `check_index_coverage` over every cited
  path. Add scopes before any negative or exhaustive claim (e.g. "no other
  caller", "fully covers").
- `indexed_no_recorded_gap` means *no recorded gap*, not completeness.
- On partial, skipped, stale, or unknown coverage: read or grep the reported
  ranges yourself before relying on the graph for that claim.
- State uncertainty. Never smooth it into a confident-sounding answer.

## 4. Investigation tiers

| Tier | Agent | Cost | Claims it may make |
|---|---|---|---|
| Scout | `codebase-memory-scout` | ~3-4 graph calls | positive, provisional only. Never absence, exhaustive, dead-code, or complete-impact claims |
| Verify | `codebase-memory` (default) | task-directed | material claims backed by exact snippets, all relevant pages |
| Auditor | `codebase-memory-auditor` | bounded scope, full | both directions, complete pagination, explicit unresolved limitations |

Use Scout for a quick provisional look, Verify by default for anything that
feeds a decision or an answer to a person, Auditor only for a bounded,
explicitly-scoped full sweep (e.g. before productionizing).

**Delegate structural investigation to the agent named for the chosen tier** —
dispatch `codebase-memory-scout`, `codebase-memory`, or
`codebase-memory-auditor` rather than investigating in the main context. Default
to `codebase-memory`. The agent's isolated context is the point: it keeps the
retrieval traffic out of this conversation's window.

These agents and the SessionStart/SubagentStart reminder hooks are registered once at user level by `codebase-memory-mcp install` — do not re-register them in this repo's settings.json.

## 5. The documentation contract

- `docs/ARCHITECTURE.md` is the human interface to this codebase. It is
  regenerated by the `poc-brief` skill, never hand-edited or allowed to drift.
- `docs/READINESS.md` is produced by the `poc-review` skill and holds the
  evidence behind a production-readiness judgement.
- Design decisions go into `manage_adr`, not into prose in these docs.
- If a change alters a component boundary, an interface, a dependency, or an
  external integration, refresh the affected section of `docs/ARCHITECTURE.md`
  in the same change — do not defer it.

## 6. Before you change code

1. `detect_changes` to map the working diff to affected symbols.
2. `trace_path(direction="both")` on every touched symbol.
3. State the blast radius before editing further.

Both directions, always — outbound-only tracing misses cross-service callers.

## 7. Never

- Never claim a POC is production-ready. This system assembles evidence; the
  engineer makes the judgement.
- Never treat the graph as ground truth — it is a retrieval mechanism over the
  source, and coverage is best-effort.
- Never claim MCP tool access that the active subagent's tool allow-list does
  not actually grant it.
- Never hand-edit `docs/ARCHITECTURE.md` or `docs/READINESS.md` — regenerate
  them with `poc-brief` / `poc-review`.
